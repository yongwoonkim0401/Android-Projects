# BigSpace 키보드

스페이스바를 **더 넓고 더 높게** 만든 Android 키보드(IME).

영문 QWERTY, 한글 두벌식, 553자 기호 팔레트, 클립보드 붙여넣기까지 들어 있지만
설계의 중심은 처음부터 끝까지 하나입니다 — **스페이스바를 빗맞히지 않는 것.**
다른 모든 결정은 이 키 하나를 지키는 쪽으로 정렬돼 있습니다.

한글 자판을 예로 든 전체 구성입니다.

```
[ 📋  회의는 목요일 오후 3시, 3층 대회의실에서… ]   ← 클립보드가 있을 때만 (20dp)

   1    2    3    4    5    6    7    8    9    0     ← 길게 누르면 ! @ # $ % ^ & * ( )
   ㅂ   ㅈ   ㄷ   ㄱ   ㅅ   ㅗ   ㅐ   ㅔ              ← 길게 누르면 - _ = + [ ] { }
   ㅁ   ㄴ   ㅇ   ㄹ   ㅎ   ㅓ   ㅏ   ㅣ              ← 길게 누르면 ; : ' " ~ / < >
   ⇧    ㅋ   ㅌ   ㅊ   ㅍ   ㅜ   ㅡ   ⌫             ← 길게 누르면 ₩ € £ · … ※

    @     :     /   ┌─────────────┐    ?    !       ← 스페이스바 옆 여백을
  ?123  한/영   ,   │    space    │    .    ⏎          2단으로 나눠 씀
                    └─────────────┘
```

배정된 기호는 각 키 **오른쪽 위 모서리에 작게** 그려집니다. 크기 조절 가능하고, 끌 수도 있습니다.

## 왜 직접 그렸나

안드로이드가 주는 `android.inputmethodservice.KeyboardView`(API 29에서 deprecated)는
**한 행(row) 안의 모든 키가 같은 높이**를 갖습니다. 즉 "스페이스바만 더 높게"가
프레임워크 차원에서 불가능합니다.

그래서 XML 자판 정의를 버리고 **배치 계산·터치 판정·렌더링을 전부 직접** 구현했습니다.
키보드 전체가 `View` 하나이고, 모든 키는 `Canvas`에 그린 둥근 사각형과 텍스트입니다.

덕분에 아래 것들이 전부 가능해졌습니다.

- 한 행 안에서 키마다 다른 높이 (스페이스바 vs 그 옆 키들)
- 한 칸을 위아래로 쪼개 쓰기 (`Key.subRow`)
- 그려진 모양과 **터치 영역을 분리**하기
- 기기 폰트에 글리프가 없는 기호를 실행 시점에 걸러내기

## 스페이스바 설계

### 1. 크기

맨 아랫줄 자체를 일반 행보다 `spaceHeightWeight`배(기본 **1.6배**) 높게 잡고,
스페이스바가 그 높이를 **전부** 차지합니다. 폭은 `spaceWidthUnits`(기본 **6칸**)입니다.

360dp 폭 화면 기준으로 **180 x 58 dp** — 일반 키(36 x 36)의 정확히 8배 면적입니다.

### 2. 터치 영역 ≠ 그려진 모양

이 키보드에서 가장 중요한 구분입니다. `PlacedKey`는 사각형을 두 개 들고 있습니다.

| | 뜻 |
|---|---|
| `hit` | 손가락을 받는 영역. 키가 차지한 **칸 전체** |
| `draw` | 실제로 칠하는 영역. `hit`를 여백만큼 줄인 것 |

그래서 키 사이의 틈은 시각적으로만 존재하고, 터치 관점에서는 **빈 픽셀이 없습니다.**
각 행 양 끝 키와 키보드 맨 위·맨 아래 키는 `hit`를 화면 가장자리까지 늘려 둡니다.
칸 밖(패딩)을 눌러도 가장 가까운 키로 보냅니다.

### 3. 레이어가 바뀌어도 움직이지 않는다

레이어는 넷(영문·한글·`?123`·기호 팔레트)인데, **네 레이어 전부에서 스페이스바의
위치와 크기가 가로세로 한 픽셀도 변하지 않습니다.** 두 가지 불변식으로 강제합니다.

| 축 | 불변식 | 상수 |
|---|---|---|
| 세로 | 모든 레이어가 정사각형 **4행** + 스페이스바 행 | `TEXT_ROWS` |
| 가로 | 스페이스바 왼쪽 **3.5칸**, 오른쪽 **2.5칸** | `LEFT_UNITS` / `RIGHT_UNITS` |

이 제약이 다른 결정들을 끌고 다닙니다. `?123` 레이어에 기호 행이 하나 더 있는 것도,
기호 팔레트가 페이지당 40개(10 x 4)인 것도 4행을 맞추기 위해서입니다.

손 기억이 깨지지 않는 것이 이 키보드의 존재 이유라, 불변식은 문서가 아니라
**테스트**로 못 박아 뒀습니다 (`KeyboardLayoutTest`).

### 4. 옆 여백을 2단으로

스페이스바가 한 줄을 다 쓰는 만큼 옆에는 세로 여백이 남습니다. 놀리지 않고
**왼쪽 2 x 3, 오른쪽 2 x 2** 격자로 나눴습니다. 윗단은 네 레이어 공통입니다.

| | 왼쪽 3.5칸 (3열) | 오른쪽 2.5칸 (2열) |
|---|---|---|
| **윗단 (공통)** | `@` `:` `/` | `?` `!` |
| 아랫단 — 영문 / 한글 | `?123` `한/영` `,` | `.` `⏎` |
| 아랫단 — `?123` | `ABC`(또는 `한글`) `한/영` `,` | `.` `⏎` |
| 아랫단 — 기호 팔레트 | `ABC` `◀` `▶` | `⌫` `⏎` |

`,` 와 `.` 는 길게 눌러도 그대로 쉼표·마침표입니다. `?` `!` 가 바로 위에 있으니까요.

구현은 `Key.subRow` 한 필드로 합니다.

| 값 | 뜻 |
|---|---|
| `null` | 줄 전체를 씀 (스페이스바) |
| `0` | 위 절반. 새 칸을 연다 |
| `1` | 아래 절반. **앞 키가 연 칸을 이어 쓴다** |

`1`이 칸을 새로 열지 않으므로, 칸 폭 합계(`KeyRow.units`)와 가장자리 확장 로직은
"키 단위"가 아니라 "칸 단위"로 돌아야 합니다.

## 정사각형 키와 전체 높이

키 높이를 dp 상수로 두지 않고 **키 폭에서 유도**합니다. 한 줄이 10칸이므로
정사각형 키의 한 변은 `화면폭 / 10`이고, 360dp 화면이면 **36dp**입니다.

| | 값 (360dp 폭 기준) |
|---|---|
| 정사각형 키 | 36 x 36 dp |
| 스페이스바 | 180 x 58 dp |
| 정사각형 행 수 | 4 (숫자 + 자모 3줄) |
| **키보드 전체 높이** | **약 202 dp** |
| 붙여넣기 줄이 떠 있을 때 | 약 222 dp |

화면이 넓으면(태블릿·가로) 정사각형 키가 터무니없이 커지므로, 전체 높이를
**화면 높이의 52%** 에서 자릅니다(`MAX_SCREEN_FRACTION`). 그때는 키가 납작한
직사각형이 됩니다. **그래서 가로 모드용 분기 코드가 따로 없습니다** — 폭 하나가
모든 걸 결정합니다.

키가 작게 느껴지면 설정의 **키 높이** 슬라이더로 정사각형의 0.8~1.4배까지 늘릴 수
있습니다(1.0 = 정사각형). 슬라이더 아래에 결과 dp와 키보드 전체 높이가 같이 표시됩니다.

## 한글 두벌식

`한/영` 키로 전환하고, 마지막에 쓰던 언어를 기억했다가 다음에 그 자판으로 뜹니다.

### 자판을 줄이고 연타로 채운다

모음 키는 **ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ ㅐ ㅔ** 8개뿐입니다. 한 줄에 10칸 대신 8칸이라
**한글 키가 영문보다 25% 넓습니다**(`HANGUL_KEY_WIDTH`). 높이는 그대로입니다.

```
ㅂ ㅈ ㄷ ㄱ ㅅ │ ㅗ ㅐ ㅔ
ㅁ ㄴ ㅇ ㄹ ㅎ │ ㅓ ㅏ ㅣ
⇧ ㅋ ㅌ ㅊ ㅍ │ ㅜ ㅡ ⌫
```

자음은 두벌식 원래 자리를 그대로 지키고, 모음은 세 칸으로 정렬됩니다 —
첫 칸이 위에서부터 **ㅗ / ㅓ / ㅜ** 라 소리 위치와 그림이 맞습니다.

`ㅣ`를 남긴 것은 의도적입니다. 연타로 유도할 수 없는 유일한 모음이라, 빼면
`이·기·시`를 못 치고 ㅚ(ㅗ+ㅣ)·ㅟ(ㅜ+ㅣ)·ㅢ(ㅡ+ㅣ)도 만들 수 없습니다.

없어진 모음은 전부 연타로 나옵니다.

| 연타 | 결과 | | 연타 | 결과 |
|---|---|---|---|---|
| `ㅏㅏ` | ㅑ | | `ㅜㅜ` | ㅠ |
| `ㅓㅓ` | ㅕ | | `ㅐㅐ` | ㅒ |
| `ㅗㅗ` | ㅛ | | `ㅔㅔ` | ㅖ |

겹모음은 서로 다른 모음의 조합이라 그대로입니다: `ㅗ+ㅏ`→ㅘ, `ㅗ+ㅐ`→ㅙ,
`ㅗ+ㅣ`→ㅚ, `ㅜ+ㅓ`→ㅝ, `ㅜ+ㅔ`→ㅞ, `ㅜ+ㅣ`→ㅟ, `ㅡ+ㅣ`→ㅢ.

### 조합기

초성/중성/종성 인덱스 세 개만 들고 도는 오토마타입니다(`HangulComposer.kt`).

- 겹받침 조합 — `ㄱㅏㅂㅅ`→값, `ㅇㅏㄴㅎ`→않, `ㄷㅏㄹㄱ`→닭
- 받침 이동 — `ㄱㅏㅂㅅㅣ`→갑시(겹받침이면 뒷자음만 넘어감), `ㅇㅏㄴㅈㅏ`→안자
- 받침이 될 수 없는 ㄸ·ㅃ·ㅉ 는 자동으로 다음 음절 초성이 됨
- 백스페이스는 글자가 아니라 **조각** 단위 — 값 → 갑 → 가 → ㄱ → (없음)
- 조합 중인 글자는 `setComposingText`로 밑줄 표시되고, 스페이스·기호·Enter·
  커서 이동 시 확정됨
- 한글 자판에서는 자동 대문자를 끕니다. Shift가 저절로 켜지면 ㅂ 대신 ㅃ가 찍히니까요

### 연타 판정

같은 자모 키를 두 번 누르면 **직전 조각을 지우고 쌍자모로 다시 넣습니다**.
그래서 초성이든 받침이든 같은 코드로 처리됩니다. 한 번 바뀌면 추적을 지우므로
**세 번째 타건은 다시 홑자모**가 되고, `있습니다`(ㅇㅣㅅㅅ**ㅅ**ㅡㅂ…)처럼
쌍받침 뒤에 같은 자음이 초성으로 오는 입력이 가능합니다.

**모음과 자음의 판정 조건이 다릅니다.**

| | 시간 제한 | 설정 스위치 |
|---|---|---|
| 모음 (`ㅏㅏ`→ㅑ) | 없음 | 없음 (항상 켜짐) |
| 자음 (`ㅅㅅ`→ㅆ) | 300ms | 끌 수 있음 |

**모음은 애매할 일이 없습니다.** 한국어 표기에서 음절의 모음 앞에는 항상 자음
(최소한 ㅇ)이 오므로, 같은 모음이 연달아 눌리는 건 복모음을 노린 경우뿐입니다.
게다가 ㅑㅕㅛㅠ는 키가 없으니 시간 제한이나 스위치에 막히면 아예 입력할 수
없게 됩니다. 그래서 무조건 동작합니다.

**자음은 반대로 원리상 애매합니다.** `학교`(ㅎㅏㄱ**ㄱ**ㅛ)와 `어깨`(ㅇㅓㄱ**ㄱ**ㅐ)는
타건 순서가 완전히 같습니다. 사전 없이는 구분할 수 없어서, 받침과 다음 초성이
같은 자음인 글자(학교·먹고·웃습·옷속…)를 빨리 치면 쌍자음으로 붙을 수 있습니다.
대응은 셋 중 하나입니다.

1. 두 자음 사이에서 잠깐(300ms) 쉰다
2. 설정에서 **자음 연타를 끄고** Shift를 쓴다
3. 붙어버렸으면 백스페이스 한 번 — 조각 단위라 갂 → 각으로 되돌아간다

## 기호 입력

### 길게 눌러 입력 (문자 자판)

**키를 300ms 이상 누르고 있으면** 그 키에 배정된 기호가 입력됩니다.
어떤 기호인지는 **키 오른쪽 위 모서리에 작게 그려져** 있어서 외울 필요가 없습니다.

| 위치 | 기호 |
|---|---|
| 숫자 행 `1`~`0` | `!` `@` `#` `$` `%` `^` `&` `*` `(` `)` |
| 첫째 줄 (`q`~`p` / `ㅂ`~`ㅔ`) | `-` `_` `=` `+` `[` `]` `{` `}` `\` <code>&#124;</code> |
| 둘째 줄 (`a`~`l` / `ㅁ`~`ㅣ`) | `;` `:` `'` `"` `~` `/` `<` `>` `` ` `` |
| 셋째 줄 (`z`~`m` / `ㅋ`~`ㅡ`) | `₩` `€` `£` `·` `…` `※` `°` |

**같은 자리는 영문·한글에서 같은 기호**입니다. 자판을 바꿔도 위치를 다시 익힐
필요가 없습니다. 한글은 줄당 키가 2개씩 적으므로 각 줄 **앞쪽 기호까지만**
배정되고, 빠지는 `\` <code>&#124;</code> `` ` `` `°` 넷은 `?123`이나 기호 팔레트에 있습니다.

여기에 스페이스바 옆 윗단의 `@` `:` `/` `?` `!` 와 아랫단의 `,` `.` 는 바로 눌러
쓰는 키입니다. 다 합쳐 **일상적인 기호 39종이 레이어를 바꾸지 않고** 들어갑니다.

숫자 행은 Shift로도 같은 기호가 나옵니다. 단 **자동 대문자로 켜진 Shift는 숫자 행에
적용되지 않습니다** — 문장 첫머리에서 `1.`을 치려는데 `!`가 나오면 곤란하니까요
(`Key.respondsToAutoShift` / `KeyboardView.shiftIsAutomatic`).

#### 모서리 힌트 크기

설정에서 조절합니다(기본 키 높이의 25%). 슬라이더는 퍼센트를 선형으로 훑지 않고
**숨김 · 20% · 25% · … · 60%** 열 칸을 지나갑니다. 20% 아래는 글자가 읽히지 않아
슬라이더 아래쪽이 통째로 쓸모없어지기 때문입니다.

키 안에서의 배치는 이렇게 잡습니다.

- **가로** — 실제 글리프 폭을 재서 오른쪽 위에 붙입니다. 폭이 넓은 `₩`·`…`를
  최대 크기로 키워도 키 밖으로 삐져나가지 않습니다.
- **세로** — 힌트가 키 위쪽에 띠(band)를 차지하고, 가운데 글자는 남은 공간의
  정중앙에 놓입니다. 힌트를 키우면 남은 공간이 좁아지므로 **가운데 글자가 따라서
  작아집니다.** 그래서 어느 크기에서도 겹치지 않습니다(60%에서는 힌트가 더 커집니다).

### `?123` 레이어

숫자 + 자주 쓰는 기호 4줄입니다.

```
1 2 3 4 5 6 7 8 9 0
@ # $ ₩ % & - + ( )
= _ [ ] < > { } \ |
기호  * " ' : ; ! ?  ⌫
```

### 기호 팔레트 (553자)

`?123` → `기호` 키로 들어갑니다. 10열 x 4행 = 한 페이지 40개, `◀`/`▶`로 넘깁니다.
현재 페이지 이름(예: `수학 2/2`)은 **스페이스바 위에 표시**됩니다 — 자리를 따로
뺏지 않으려고 그렇게 했습니다.

수록 분류: 문장부호 · 괄호 · 수학 · 통화 · 단위 · 화살표 · 도형 · 기호 · 원문자 ·
그리스 · 숫자 · 라틴 확장 — **총 553자, 21페이지**.

기기 폰트에 글리프가 없는 문자는 `Paint.hasGlyph`로 걸러내고 페이지를 다시 짭니다.
그래서 두부(□)가 뜨는 자리가 없고, 페이지 수는 기기에 따라 조금 달라질 수 있습니다.

## 붙여넣기 스트립

클립보드에 글자가 있으면 **자판 맨 위에 얇고 긴 줄**이 하나 붙습니다.
클립보드 앞부분을 말줄임으로 보여주고, 누르면 전체가 붙습니다.
무엇이 붙을지 보고 누르는 게 요점이라 아이콘을 뺀 나머지 폭을 전부 글자에 씁니다.

- 높이는 일반 키의 0.55배(약 20dp). **클립보드가 비어 있으면 줄 자체가 없습니다** —
  평소 키보드 높이는 그대로입니다
- 붙여넣고 나면 사라집니다. 다시 복사하거나 다른 입력란으로 옮기면 나옵니다
- 여러 줄 텍스트는 공백을 눌러 한 줄로 보여줍니다 (붙는 건 원본 그대로)
- **비밀번호 입력란에서는 뜨지 않습니다.** 복사한 앱이 민감 정보로 표시한 클립
  (`ClipDescription.EXTRA_IS_SENSITIVE`, API 33+)도 감춥니다

Android 10부터 클립보드는 포커스를 가진 앱만 읽을 수 있는데 **기본 입력기(IME)는
예외**라 키보드가 떠 있는 동안 읽을 수 있습니다. 복사 즉시 반영되도록
`OnPrimaryClipChangedListener`도 걸어 뒀습니다.

## 그 밖의 입력 동작

| 동작 | 내용 |
|---|---|
| Shift | 한 번 탭 = 한 글자만 대문자, 빠르게 두 번 탭 = Caps Lock (키가 파랗게 점등) |
| 자동 대문자 | 입력란의 힌트(문장 시작 등)를 따라 Shift 자동 활성화. 한글 자판에서는 끔 |
| Backspace | 길게 누르면 가속 반복 삭제. 서로게이트 페어(이모지)는 한 번에 삭제 |
| Enter | 입력란이 요구하는 동작(검색/다음/완료 등)을 우선 수행, 없으면 줄바꿈 |
| 스페이스바 드래그 | 좌우로 끌면 커서 이동 |
| 슬라이드 교정 | 손가락을 **뗄 때** 위치로 입력되므로, 잘못 눌렀어도 떼기 전에 끌어서 고칠 수 있음 |
| 미리보기 | 누른 글자가 키 위에 크게 뜸. 길게 눌러 기호가 나가면 그 기호로 바뀜 |
| 다크 모드 | `values-night/colors.xml` |

## 설정

앱을 실행하면 설정 화면이 뜹니다. 시스템 설정에서도 이 화면으로 들어옵니다
(`method.xml`의 `settingsActivity`).

### 키 크기 · 반응 세기

| 항목 | 범위 | 기본값 |
|---|---|---|
| 스페이스바 폭 | 4.0 ~ 8.0칸 | 6.0칸 (아랫줄의 50%) |
| 스페이스바 높이 | 일반 키의 1.0 ~ 2.2배 | 1.6배 |
| 키 높이 | 정사각형의 0.8 ~ 1.4배 | 1.0배 (정사각형) |
| 모서리 기호 힌트 크기 | 숨김 / 20 ~ 60% | 25% |
| 진동 세기 | 0 ~ 100% | 50% |
| 키 소리 크기 | 0 ~ 100% | 60% |

슬라이더는 모두 **0이 곧 끄기**입니다. 힌트 크기 0이면 힌트가 사라지고(길게 누르기는
그대로 동작), 진동·소리 0이면 꺼집니다. 그래서 켬/끔 스위치를 따로 두지 않았습니다.

진동 세기는 `performHapticFeedback`으로는 조절이 안 되므로 `Vibrator`를 직접 씁니다.
진폭 제어가 되는 기기는 18ms 고정 펄스의 **진폭**을 조절하고, 안 되는 기기는 그럴 수
없으므로 **펄스 길이**(8~40ms)로 세기를 흉내 냅니다.

키 소리는 시스템 효과음(`AudioManager.playSoundEffect`)을 씁니다.
**시스템 설정에서 '터치 사운드'가 꺼져 있으면 여기서 올려도 소리가 나지 않습니다.**

### 입력 느낌 (토글)

- 누른 글자 미리보기
- 스페이스바 좌우 드래그로 커서 이동
- 같은 자음 연타로 쌍자음 (모음 연타는 이 설정과 무관하게 항상 동작)

### 미리보기 키보드

설정 화면 하단에는 **실제 `KeyboardView`가 그대로 붙어** 있습니다.
IME를 활성화하기 전에도 슬라이더를 움직이며 크기를 손으로 확인하고, 테스트
입력창에 바로 쳐볼 수 있습니다. 한글 조합·기호 팔레트·붙여넣기까지 전부 동작합니다.

설정은 `SharedPreferences`에 저장되고 키보드가 뜰 때마다 다시 읽습니다.

## 코드 구조

```
app/src/main/java/com/example/bigspacekeyboard/
├── KeyboardModel.kt            키/행 데이터 모델 + 레이어별 자판 정의
├── KeyboardView.kt             Canvas 렌더링 · 배치 계산 · 터치 판정
├── HangulComposer.kt           두벌식 오토마타 (Android 의존 없음)
├── SymbolCatalog.kt            기호 553자 목록 + 글리프 필터 + 페이지 구성
├── KeyPrefs.kt                 SharedPreferences ↔ KeyboardConfig
├── BigSpaceKeyboardService.kt  InputMethodService
└── MainActivity.kt             설정 화면 + 미리보기 키보드
```

### 핵심 타입

| 타입 | 역할 |
|---|---|
| `Key` | 키 하나. `width`(칸), `subRow`(줄 안 위치), `shiftOutput`, `longPress` 등 |
| `KeyRow` | 한 줄. `heightWeight`(줄 높이 배율), `sideGap`, 그리고 칸 합계 `units` |
| `PlacedKey` | 배치가 끝난 키. `hit`(터치)와 `draw`(그리기) 사각형을 따로 들고 있음 |
| `KeyboardConfig` | 사용자가 조절하는 값 전부 (data class, 불변) |
| `Layer` | `LETTERS` · `HANGUL` · `SYMBOLS` · `SYMBOL_PAD` |

### 흐름

```
터치  →  KeyboardView.onTouchEvent
             │  hit 사각형으로 키를 찾고, 길게 누르기/반복 타이머를 걸고
             ↓
         OnKeyboardActionListener.onKey(code, output)
             │
             ↓
      BigSpaceKeyboardService.onKey
             │  한글이면 HangulComposer로, 아니면 그대로
             ↓
         InputConnection.commitText / setComposingText
```

레이어 전환·Shift 상태 같은 판단은 전부 서비스에 있고, `KeyboardView`는
"무엇이 눌렸는지"만 알려줍니다. 그래서 같은 뷰를 설정 화면에서 그대로 재사용할 수
있습니다 — 거기서는 `MainActivity`가 같은 인터페이스를 구현해 `EditText`에 씁니다.

### 빌드 환경

Kotlin · AGP 8.7.3 · Gradle 8.9 · minSdk 24 · targetSdk 34 · Material 3 · viewBinding.
외부 의존성은 AndroidX와 Material 뿐입니다.

## 테스트

로직 중 Android에 의존하지 않는 부분(오토마타, 자판 배치)은 JVM 유닛 테스트로
검증합니다. 에뮬레이터가 필요 없습니다.

```bash
./gradlew testDebugUnitTest
```

**`HangulComposerTest`** — 조합기 20개

기본 음절 · 복합 모음 · 겹받침 · 받침 이동 · 쌍자음 · 홀로 남은 자모 ·
백스페이스 · 연타(자음/모음/간격/스위치/세 번째 타건).
연타 판정이 `SystemClock`을 직접 읽지 않고 **시각을 인자로 받기 때문에**
"400ms 간격이면 안 붙는다", "학교는 사이를 쉬면 제대로 들어간다" 같은 타이밍
의존 동작까지 시계 없이 결정적으로 테스트됩니다.

**`KeyboardLayoutTest`** — 배치 불변식 9개

네 레이어 전부에 대해 검사합니다.

- 정사각형 4행 + 스페이스바 행 = 5행
- 글자 줄은 모두 10칸
- 스페이스바 왼쪽 3.5칸 / 오른쪽 2.5칸 / 폭 6칸
- 스페이스바 옆 윗단은 `@ : / ? !`, 아랫단과 짝이 맞음
- 쉼표·마침표에 롱프레스 없음
- 한글 모음은 여덟 개
- 클립보드가 없으면 붙여넣기 줄도 없고, 있으면 맨 위에 짧은 줄이 붙음

레이어에 키를 더하다 스페이스바가 밀리면 빌드가 바로 깨집니다.

## 설치와 빌드

1. Android Studio로 이 폴더를 열고 실행 (`app` 모듈)
2. 앱 실행 → **시스템 설정에서 켜기** → 목록에서 "BigSpace 키보드" 체크
3. 앱으로 돌아와 **입력기 선택** → "BigSpace 키보드" 선택

앱이 현재 상태(활성화됨 / 선택됨)를 감지해서 남은 단계를 안내합니다.

```bash
./gradlew assembleDebug      # 디버그 APK
./gradlew testDebugUnitTest  # 유닛 테스트
```

릴리스 서명은 `keystore.properties`(gitignore 대상)에서 읽습니다.
`keystore.properties.example`를 복사해 채우면 되고, 파일이 없으면 릴리스 빌드가
그냥 서명되지 않은 채로 나옵니다.
